# LearnLens MVP API contract

Node.js 22.13+, built-in HTTP server with pinned document/speech dependencies, locally on 127.0.0.1:3210. Vanilla HTML/CSS/ES modules frontend. No build step. Keys stay in server memory, never persisted. Uploaded documents/media and prepared parts temporarily use private host OS storage; see IMPORTS.md for cleanup and crash caveats. Non-secret settings also session-only for this release. Each browser gets an isolated HttpOnly SameSite cookie + CSRF token. Idle expiry 1 hour; absolute 12 hours. Hosted private-beta mode requires HTTPS PUBLIC_ORIGIN and LEARNLENS_ACCESS_PASSWORD (16+ chars), adds Secure cookies, and permits only public HTTPS provider destinations with checked/pinned IPs. Not a full account/auth platform; see README before hosting.

All /api routes require X-LearnLens-Token header from meta[name=learnlens-token]. Server replaces __APP_TOKEN__ in public/index.html. JSON mutation routes require application/json. Errors: {error: string}, appropriate non-2xx. All data/keys untrusted; use textContent, not innerHTML. Model capabilities cannot be determined from GET /models alone.

## GET /api/state
{locked:boolean,providers:[{id,name,baseUrl,hasKey,models:[{id}],checks:{[modelId]:{text?:{status,detail,checkedAt,api,voice?},vision?:...,speech?:...,transcription?:...,video?:...}}}],roles:{primary: Role|null,transcription: Role|null,speech: Role|null,video?:Role|null}}
Role = {providerId,model,api:'auto'|'chat'|'responses'|'gemini',voice?:string,reasoningEffort?:'none'|'minimal'|'low'|'medium'|'high'|'xhigh'|'max',timeoutSeconds?:number,fps?:number}. `gemini` is available for explicit transcription and video roles; primary still accepts only auto/chat/responses. For transcription, `auto` means multipart (no fallback); legacy chat/responses values retain multipart behavior. Thinking level is primary-only; omitted or 'default' is normalized to omitted. Responses sends reasoning.effort; Chat sends reasoning_effort. Support varies by model; no silent downgrade on rejection.

`timeoutSeconds` is independently configurable for primary and video: an integer from **30 to 600**, default **300** when omitted. It round-trips only when explicitly supplied; it is never forwarded as a provider parameter. Recognition, model preparation notes, teaching, text/vision probes and model advice use this deadline. Each HTTP attempt has one total deadline spanning DNS/connect/upload, response headers and the full body; chunks do not reset it. Existing Auto fallback on HTTP 404/405/501 is a separate attempt with the same budget. Timeout, malformed output and other errors never trigger automatic retry. Transcription/speech remain at 100 seconds and discovery at 20 seconds. Existing job/session/concurrency quotas are unchanged; longer requests occupy a job longer. Saving a new wait limit increments `setupRevision` without dispatching anything; continuation needs renewed consent and reuses successful checkpoints.

Transport diagnostics include `timeoutMs`; a local deadline expiry returns 504 with `timeoutPhase:'response_headers'|'response_body'`. The former means no response headers had arrived, not that the provider never received the request. Known upstream HTTP errors remain HTTP errors even if their bounded error-body read stalls. Larger limits cannot override a gateway/proxy's own cutoff or guarantee cancellation/billing outcomes. Native HTTP(S) is used for deadlines above 300 seconds to avoid the built-in fetch five-minute ceiling, and for hosted DNS pinning. It requests identity encoding; a gateway that nevertheless returns compressed successful responses is rejected explicitly without replay. Public HTTPS/DNS, redirect and body-size safeguards remain enforced.

Speech may instead be {engine:'kokoro',model,api:'auto',voice}. The model is canonicalized from operator configuration. Browser-supplied private URLs are never accepted for this engine. api selects the primary, transcription or native-video protocol; speech uses /audio/speech compatibility endpoint. Speech is OPTIONAL (some direct OpenAI models need protocols not implemented yet). Never assume a model name guarantees endpoint support. Allow manual model ID for providers without listing support.

State also returns `setupRevision` (integer), `starter: {role,reason}|null` and `speechServices: {kokoro:{available,bundled,languages,voices,model,voice,checks}}`. The starter is a non-billable built-in rule over listed models/sample checks, not an AI inference or a capability guarantee. Kokoro checks are keyed by voice. Managed endpoint URLs/keys are not returned. With normal native `npm start` or the optional Docker package, new sessions have the Kokoro speech role selected by default without learner setup. Clearing the session restores this built-in default; users can explicitly select online speech or clear speech.

## POST /api/login
{password} => {ok:true}. Hosted access-password gate (not provider API key). GET state is available before login with locked=true and empty settings. Other routes are denied until authenticated.
## POST /api/logout
{} => {ok:true}. Clear this browser's provider keys and roles. Hosted mode locks the session again. In-flight external requests are not cancelled or undone. Their stale responses are rejected, and no follow-on speech requests start after logout. Local processing is cancelled and server-staged materials are removed.

## POST /api/providers
{name,baseUrl,apiKey} => {provider: publicProvider}
Base URL includes API prefix, e.g. https://api.openai.com/v1 or https://gateway.example/api/v1. Remove trailing slashes, don't append a second /v1. HTTP permitted only localhost/127.0.0.1/[::1] for locally hosted providers. API key optional for local providers, required for remote. Keys are write-only. Add multiple providers (or edit an existing connection with PUT).
## PUT /api/providers/:id
{name,baseUrl,apiKey?} => {provider: publicProvider}. Keeps provider ID and model-role references. Blank API key retains the existing key only when the normalized URL is unchanged; changing to a remote URL requires re-entering a key. A changed URL/key clears listed models and sample checks. Rejects during an active AI job. No upstream request is made by editing.
## DELETE /api/providers/:id
=> {ok:true}; clears roles referencing that provider.
## POST /api/providers/:id/discover
{} => {models:[{id}]} from /models. Empty list and unsupported endpoint should explain manual model entry, not block saving provider.
## POST /api/providers/:id/probe
{model,kind:'text'|'vision'|'speech',api:'auto'|'chat'|'responses',voice?:string,reasoningEffort?:string,timeoutSeconds?:number,consent:true} => {check:{status:'verified'|'failed',detail,checkedAt,api,voice?}}
Optional explicit tiny billable requests. UI must label paid tests and request confirmation. Text/vision use primary API selection. Vision tests image understanding, not mere payload acceptance. Checks include reasoningEffort and timeoutSeconds when explicitly configured and are scoped to the selected primary API mode/thinking level/wait limit or speech voice; changing these settings makes the relevant badge untested until another check succeeds. Speech probes one short line; transcription is verified after a real upload, not a synthetic fake test, and is scoped to multipart versus Gemini-native mode.
## PUT /api/roles
{primary:Role|null,transcription:Role|null,speech:Role|null,video?:Role|null} => {roles}
Video requires `api:'gemini'`, optional finite `fps` from 1 through 24 (default 24), and independent `timeoutSeconds` from 30 through 600 (default 300). FPS is video-only. Omitting `video` in a legacy three-role update preserves an existing assignment; explicit null clears it. Empty legacy server state can omit the video key. Video assignment is manual; the model-advisor endpoint below does not recommend it. Accepted native receipts establish structural response compatibility, not complete perception.
Return selected model roles/count in UI; roles may reuse providers/models. Primary required to generate but can save null. Manual model IDs allowed. No fictitious model recommendations; show user-selected roles and untested status.

## POST /api/roles/recommend
{primary?:Role,scope?:'primary'|'all',consent:true} => {summary,suggestions:[{role:'primary'|'transcription'|'speech',selection:Role|null,reason,caveat}],warnings,advisor:Role}.
Uses the submitted primary draft or saved primary, including its thinking level and request wait limit. Primary suggestions preserve that wait limit even when selecting a different model; model output cannot override it. Explicit consent is required. Default scope includes only the primary provider; all scope shares other providers' catalogs with the primary advisor. Only catalog IDs, provider display names, scoped sample-check metadata and configured Kokoro availability are sent. No keys, base URLs, lesson material or internal provider IDs. Catalog includes listed and already-selected manual IDs; maximum 600 candidates. Unknown output candidates, invalid schema or settings changes during the call fail safely. Uses the normal AI job/session limits. Does not save roles or mark capability checks verified. UI renders text safely, lets users select which suggestions fill the draft, and requires a separate Save. Null selections mean abstain/preserve current choice.

## POST /api/speech/kokoro/probe
{voice?:string,consent:true} => {check}. Uses the included worker in the standard deployment, or an advanced operator-configured service. The service URL never comes from browser input. The app-only `npm run start:lite` developer mode without an external service returns a clear unavailable error. Native managed speech uses authenticated loopback HTTP with WAV output; its internal URL/token are never returned. `languages:['en']` and `voices` describe the native runtime's supported IDs; null means coverage is not advertised by an external/container service. Generates a short synthetic line and records the voice-specific result. Explicit local-test confirmation; no automatic cloud fallback. A returned supported audio format is not proof of naturalness or language quality.

## POST /api/lessons
{text:string,images:[{name,dataUrl}],language:string,level:string,subject:string,goal:string,includeAudio:boolean,consent:true,sourceWarnings?:string[],expectedSetupRevision?:number} => {id,title,html,warnings:[string],lesson:LessonSpec}
text up to 40k chars; up to 5 PNG/JPEG/WebP images, 4MB each and 8MB combined decoded; total HTTP body 13MB. These are final-request limits, not original-file cutoffs. The unified frontend automatically processes all document/media parts and reduces larger sources through consented digests first. Clipboard paste, drag/drop and file picker supported. sourceWarnings is bounded to 30 strings of at most 500 characters and persists into the export. Images require primary model vision capability; if untested show warning but let user request with data-processing notice. Inputs sent only to chosen provider on generate. Lesson model returns validated JSON and trusted renderer makes HTML; never execute arbitrary model HTML/JS. The complete-audio composer sends `includeAudio:false` here and uses the separate plan endpoints below. For backward compatibility only, `includeAudio:true` generates up to 8 sentences from lesson.audio using the selected provider speech role or configured Kokoro engine. Failures keep valid text lesson with warnings, never claim audio exists. User explicitly initiates paid generation. No pronunciation scoring yet. All subjects primary through university via free-form subject + AI auto-detect; depth/correctness requires human review.

LessonSpec = {title,subject,level,language,englishLearning?:boolean,summary,objectives:[string],sections:[{type:'explanation'|'steps'|'example'|'vocabulary'|'quiz'|'summary',title,body:string,items:[string],question:string,answer:string,translation:string,source:string,readingPauses?:boolean}],audio:[{text,translation,readingPauses?:boolean}],warnings:[string]}. Fields required except the optional boolean metadata (empty strings/arrays okay); max 16 sections, 8 legacy `audio` script entries. Complete-mode targets are independently derived from every retained learning field and original source, not this legacy sample array. Flexible section order/type chosen by AI/request. Plain text math in MVP, no arbitrary scripts or diagrams. Source labels from provided input, never fabricated page references. HTML output is self-contained with escaped content, embedded generated audio, 1x/.75x/.5x speed, revealable hints/answers and source labels. It contains no credentials or external calls.

`englishLearning` describes an English-learning subject, independently of explanation language. It is model-reported, not certified; omission remains compatible and invalid nonboolean values reject. The composer defaults to Auto and resolves explicit On/Off, then any selected subject, then this metadata (or a conservative legacy subject-label fallback). This does not change the server's explicit `includeAudio`/consent contract or automatically invoke speech on `/api/lessons`.

`readingPauses:true` explicitly marks generated chunked-reading prose. For sections it applies to body/items/question/answer, never title/translation; audio entries opt in independently. Spaced single `/` markers normalize to punctuation only for synthesis. Display/source text and exact offsets remain unchanged; clip identities hash normalized speech pieces. Existing punctuation is preserved without duplicate pauses; numeric fractions/single-letter ratios/compact URL/path/IPA forms have defensive exclusions. Unmarked meaningful alternatives and uploaded originals are never globally rewritten. The legacy sample-audio API uses the same speech-only normalization.

## Complete English audio plans

All endpoints retain authorization, same-origin and session-token checks. Plans and clip IDs are owner-scoped; no client filesystem paths or client-generated HTML are accepted. See [FULL-AUDIO.md](FULL-AUDIO.md) for coverage/language limits, privacy, quotas and session-only recovery.

- `POST /api/audio/preflight {}`: local managed-encoder and capacity checks, no AI/probe; may prepare pinned media assets. Returns `{ready,limits}`.
- `POST /api/audio/extract {image:{dataUrl},consent:true,expectedSetupRevision}`: one primary-model image recognition request. Both literal consent and the **current integer revision are mandatory**. Returns `{text,coverage:'complete'|'uncertain'|'no_english',warnings}`. All readable original English is requested, never a digest; even `complete` is not independent OCR verification. Maximum decoded image 4 MiB, recognized text 40,000 characters; the effective output-token budget remains 10,000 (the old role-level `maxTokens:12000` was ignored, not a larger wire budget). No automatic retry after malformed/truncated/failed output.
- `POST /api/audio/plans {id:UUID,lesson:LessonSpec,images?:[],sourceText?:string,warnings?:[],expectedSources:[sourceKey],expectedSetupRevision}`: local creation with validated lesson/images and immutable speech identity. Same ID/content is idempotent; conflicting content is rejected. No provider request. Returns a manifest.
- `POST /api/audio/plans/:id/sources {source:{key,text,source,extraction,coverage,warnings}}`: add one declared source. Text is at most 40,000 UTF-16 characters; source label at most 300. `extraction` is `text|transcription|vision|unavailable`; `coverage` is `complete|uncertain|no_english|unavailable`. Identical key/content replay is local/idempotent; conflicts return409. The frontend automatically batches longer text without dropping tails.
- `POST /api/audio/plans/:id/seal {}`: require every declared source; freeze the deterministic inventory. No speech is dispatched.
- `GET /api/audio/plans/:id`: `{id,setupRevision,speech,summary,clips,sourceKeys,warnings}`. Summary includes `status:collecting|ready|partial|complete`, `totalClips`, `completedClips`, `totalUnits`, `sourceCount`, `expectedSources`, `bytes`, and separate `sourceUncertainties`. Clip views contain ID, status, attempt count and optional safe failure text, not source text or credentials.
- `POST /api/audio/plans/:id/reconfirm {consent:true,expectedSetupRevision}`: local adoption of the current revision **only if speech engine/provider base/model/voice still match**. A new voice/destination cannot silently reuse a plan. No provider request.
- `GET /api/audio/plans/:id/clips/:clipId`: `{clip,summary}`, strictly read-only status polling.
- `POST /api/audio/plans/:id/clips/:clipId {consent:true,expectedSetupRevision,attemptId:UUID,retry?:true}`: one small speech operation. Exact current revision and plan binding are mandatory. Capture the attempt before dispatch; a repeated attempt ID never causes another provider request. Completed clips are reused; failed/unknown/damaged clips need a new attempt ID and explicit retry consent. A retained raw speech result is encoded locally on recovery without repeating speech. Statuses: `pending|processing|complete|failed|encoding_failed|damaged`. A replay can return HTTP200 with a failed/processing status; callers must inspect it, not assume success. No speech endpoint fallback.
- `GET /api/audio/plans/:id/export`: trusted `{id,title,lesson,html,warnings,audioSummary}` with available MP3 assets embedded once. Verifies cached file hashes; damage downgrades coverage. Incomplete inventories/clips are explicitly labeled, never silently treated as complete. Busy export/clip operations return409; export itself never generates audio.
- `DELETE /api/audio/plans/:id`: cancel queued local work and remove owned temporary data. Already submitted provider work cannot be undone. Cleanup failures retain ownership/reservation for retry; no late results may resurrect a deleted plan.

All new inference endpoints use literal consent and mandatory revision checks. The UI shows an exact-count speech confirmation and stops on any failed/unknown paid attempt. Before an audio plan exists, Subject Auto may require an inventory-only upgrade after teaching: local parts are reread, transcripts and acknowledged OCR come from the pinned preparation job, and only missing image recognition is sent with approved primary settings/revision. This uses no new transcription/digests/merges/teaching. New lessons/attachment edits are blocked until that inventory completes or is explicitly discarded. Continuation of unfinished OCR requires renewed consent showing current settings; normal plan-ID continuation after inventory completion never reruns `/lessons`, source recognition or transcription. Unchanged-setup continuation can poll an in-flight clip without issuing a rebind write; changed setups wait for the existing operation before reconfirming. Encoding-recovery clips are resolved before other damaged clips because only one bounded raw result is retained per plan.

## Local material staging (no provider calls)
All routes retain session ownership/CSRF checks. `POST /api/materials` accepts `{id:clientUUID,name,size,analysisMode?:'whole-video'|'sampled-stills'}`; repeating the same ID/name/size is idempotent. `GET /api/materials/:id` returns `{id,name,size,received,status,kind,partCount,duration?,hasAudio?,hasVideo?,pages?,warnings,error,chunkSize:4194304}`.

`PUT /api/materials/:id/content?offset=N` takes raw `application/octet-stream` bytes (at most 4 MiB). Upload sequentially; an identical chunk replay is safe, different content/offset conflicts return 409. `POST /api/materials/:id/finish` with `{}` performs bounded local extraction/probing and returns the manifest. `POST /api/materials/:id/parts` with `{index}` returns `{index,label,source,text,images,audio?,warnings,start?,end?}`. `DELETE /api/materials/:id` aborts local work and removes staging. No filesystem paths are accepted from clients. See IMPORTS.md for resource ceilings and format fidelity.

An earlier direct-document endpoint `POST /api/materials/import` also accepts bounded document bytes with `X-LearnLens-Filename`; the unified UI uses resumable staging instead.

## URL acquisition and native-video plans

All routes require session ownership, same-origin/CSRF checks and existing resource limits. Retrieval/local preparation makes no AI inference request.

- `POST /api/materials/from-url {id:UUID,url,mode?:'auto'|'webpage'|'video'|'audio',publicFetchConsent:true}` → HTTP 202 material status. Literal fetch consent is separate from AI consent. HTTPS/public-DNS/port-443 rules apply even on localhost deployments. Same ID + normalized URL/mode is idempotent; a failed acquisition is not restarted. Explicit reimport needs a new ID.
- `GET /api/materials/:id` is read-only and includes `snapshotReady`, `snapshotId`, `sourceHash`, `analysisMode`, redacted `provenance`, and optional `cleanupPending`. Complete acquisition is sealed before local text parsing. `POST .../:id/finish {}` can retry failed local processing of that snapshot, never download it again. Deletion waits for owned work; physical deletion failures retain quota accounting.
- Whole-video `POST .../:id/parts {index}` returns `videoRef:{materialId,snapshotId,index}`, bounds and metadata, not MP4 bytes, extracted WAV or stills. Native timing attestations/filesystem paths remain private and are not accepted from clients.
- `GET /api/materials/:id/video-plan?fps=24` finds an existing plan only (404 if absent). `POST` to the same path with `{fps}` creates/returns a local immutable plan, HTTP 201. Plan identity binds the snapshot, profile and FPS; no inference occurs here.
- `GET /api/video/plans/:planId` and `GET .../:planId/clips/:clipId` read status/verified receipts only. IDs are 64 lowercase hexadecimal characters. Clips expose status, `working`, attempt metadata and safe failure diagnostics, plus successful analysis when available. Status includes pending/processing/complete/failed/checkpoint_failed/damaged.
- `POST /api/video/plans/:planId/clips/:clipId {consent:true,expectedSetupRevision,attemptId:UUID,retry?:boolean}` → HTTP 202. New work requires the current video setup/revision, checked again after local clipping immediately before provider dispatch. Same attempt never redispatches; busy/complete receipts are reused. Failed/damaged work requires explicit retry and a new UUID. Accepted output with failed checkpoint publication is repaired locally before current role/revision requirements; poll while `working:true`, including during checkpoint_failed.
- `POST /api/lessons` additionally accepts `videoPlans:[{materialId,snapshotId,planId}]`. Every attached whole-video material must be ready and represented exactly; every interval's actual saved receipt is verified server-side before teaching. A client completion claim cannot bypass this gate.

One native request supplies a canonical local MP4 of at most 8 MiB / 30.5 seconds to the explicitly configured Gemini endpoint, with `videoMetadata.fps`, one candidate and 8192 output tokens. Exactly one STOP candidate must contain the bounded strict analysis schema; every five-second window separates raw transcript/visible text from observations and uncertainty. No schema repair, audio/still fallback, automatic retry or extra native/STT/OCR analysis for subsequent English audio inventory. See [source limits, privacy, acquisition modes and host setup](URL-SOURCES.md).

Video diagnostics allow bounded timing/status/category metadata with a templated `/models/{model}:generateContent` endpoint; no raw URL, filenames, source/model-output prose or response body. `providerRequested` records dispatch, not billing/completion/cancellation. Model-reported coverage does not prove every frame/word was understood. Whole-video plans are session-only, not restart-safe durable jobs.

## POST /api/materials/summarize
`{consent:true,text,images,source,goal,expectedSetupRevision?:number}` => `{text,warnings,preparationMode:'verbatim'|'model'}`. Image-free text already within the 2,200-character notes budget is retained locally without a provider request (`verbatim`), after existing input validation/boundary trimming. Longer text or any images use the primary model (`model`). This does not bypass transcription or final teaching. Consent, setup-revision, session and CSRF guards still apply to both modes. The UI labels local preparation separately from provider inference.

Model notes remain strictly bounded: a JSON object with nonempty `notes` (hard maximum **8,000 decoded UTF-16 code units**, checked before existing boundary trimming) and `warnings` (0–5 nonempty strings, each at most 300 characters). **2,200 remains the soft model target and local passthrough threshold**, not the model-response rejection boundary. Valid 2,473-character notes, for example, are retained without clipping or another paid rewrite. Internal text is preserved exactly; established outer whitespace trimming is unchanged. Malformed/empty/control-containing or over-hard-limit notes are never accepted as a checkpoint, truncated, repaired through another paid call or silently retried. The prompt still asks for compact notes below 2,200; models may overshoot that target within the hard bound. The 2,000-output-token budget and configured thinking remain unchanged. Hierarchical reduction retains the 35,000-character aggregation target and 40,000-character request ceiling; nonprogress fails explicitly rather than truncating sources.

A local validation failure returns HTTP 502 with `diagnostics.category:'preparation_validation'`, a fixed `validationReason` such as `digest_invalid_json`, `digest_notes_limit` or `digest_warning_limit`, and relevant character/count metadata. Sanitized upstream HTTP status, endpoint, response byte count, completion status and reported token counts are preserved when available. Thus app HTTP 502 can be distinguished from provider HTTP 200 with invalid notes. Bodies, notes, warning text, instructions, source labels and credentials are omitted from diagnostics. Explicit incomplete/refusal/tool-request text responses fail before notes validation; legacy omitted completion metadata remains supported, not independently verified.

The client performs bounded hierarchical reduction when necessary. Successful local and model preparation results are pinned in the current page's generation checkpoint; explicit continuation reuses them and retries only unfinished steps after renewed consent. Saved instructions/options apply; changed attachments block continuation. Reload, logout, expiry or app restart loses the checkpoint. No persistent browser storage is used.

`/materials/summarize`, `/transcribe` and `/lessons` require `consent:true` and reject a supplied stale `expectedSetupRevision` before invoking a provider. Legacy direct API callers must now include `consent:true`; the unified UI already supplies it only after confirmation. All new UI calls capture the revision when consent is given; the optional field preserves existing API clients. Paid calls are never automatically retried after a malformed, timed-out or unknown result. The narrowly scoped 404/405/501 Responses→Chat fallback remains the exception for primary API auto mode, never transcription.

## POST /api/transcribe
{dataUrl:'data:audio/wav;base64,...',name?:'recording.wav',consent:true,expectedSetupRevision?:number} => {text}
Default: selected provider `/audio/transcriptions` multipart. Accept webm,wav,mp3,mp4,ogg; <=8 MiB. Explicit transcription `api:'gemini'`: inline prepared WAV only, one non-streaming native `models.generateContent` call on the same provider. `/v1` becomes `/v1beta`, custom prefixes remain; other supported base shapes, authentication, model-ID constraints, response validation and limits are in [GEMINI-AUDIO.md](GEMINI-AUDIO.md). No model-name inference or native/multipart fallback, even on 404/405/501. Blocks, truncation, missing/non-text/empty output and the no-speech prompt sentinel fail without accepting a transcript. Frontend record via MediaRecorder if supported plus audio upload fallback. Ask before sending microphone data, stop tracks, show pending state. Automatic media preparation supplies independently playable WAV parts; successful transcripts are cached in-page and enter source-labeled preparation. No claims that transcription measures pronunciation.
