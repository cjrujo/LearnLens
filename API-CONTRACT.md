# LearnLens MVP API contract

Node.js 22.13+, built-in HTTP server with pinned document/speech dependencies, locally on 127.0.0.1:3210. Vanilla HTML/CSS/ES modules frontend. No build step. Keys stay in server memory, never persisted. Uploaded documents/media and prepared parts temporarily use private host OS storage; see IMPORTS.md for cleanup and crash caveats. Non-secret settings also session-only for this release. Each browser gets an isolated HttpOnly SameSite cookie + CSRF token. Idle expiry 1 hour; absolute 12 hours. Hosted private-beta mode requires HTTPS PUBLIC_ORIGIN and LEARNLENS_ACCESS_PASSWORD (16+ chars), adds Secure cookies, and permits only public HTTPS provider destinations with checked/pinned IPs. Not a full account/auth platform; see README before hosting.

All /api routes require X-LearnLens-Token header from meta[name=learnlens-token]. Server replaces __APP_TOKEN__ in public/index.html. JSON mutation routes require application/json. Errors: {error: string}, appropriate non-2xx. All data/keys untrusted; use textContent, not innerHTML. Model capabilities cannot be determined from GET /models alone.

## GET /api/state
{locked:boolean,providers:[{id,name,baseUrl,hasKey,models:[{id}],checks:{[modelId]:{text?:{status,detail,checkedAt,api,voice?},vision?:...,speech?:...,transcription?:...}}}],roles:{primary: Role|null,transcription: Role|null,speech: Role|null}}
Role = {providerId,model,api:'auto'|'chat'|'responses'|'gemini',voice?:string,reasoningEffort?:'none'|'minimal'|'low'|'medium'|'high'|'xhigh'|'max'}. `gemini` is transcription-only; primary still accepts only auto/chat/responses. For transcription, `auto` means multipart (no fallback); legacy chat/responses values retain multipart behavior. Thinking level is primary-only; omitted or 'default' is normalized to omitted. Responses sends reasoning.effort; Chat sends reasoning_effort. Support varies by model; no silent downgrade on rejection.
Speech may instead be {engine:'kokoro',model,api:'auto',voice}. The model is canonicalized from operator configuration. Browser-supplied private URLs are never accepted for this engine. api selects the primary or transcription protocol; speech uses /audio/speech compatibility endpoint. Speech is OPTIONAL (some direct OpenAI models need protocols not implemented yet). Never assume a model name guarantees endpoint support. Allow manual model ID for providers without listing support.

State also returns `setupRevision` (integer), `starter: {role,reason}|null` and `speechServices: {kokoro:{available,bundled,languages,voices,model,voice,checks}}`. The starter is a non-billable built-in rule over listed models/sample checks, not an AI inference or a capability guarantee. Kokoro checks are keyed by voice. Managed endpoint URLs/keys are not returned. With normal native `npm start` or the optional Docker package, new sessions have the Kokoro speech role selected by default without learner setup. Clearing the session restores this built-in default; users can explicitly select online speech or clear speech.

## POST /api/login
{password} => {ok:true}. Hosted access-password gate (not provider API key). GET state is available before login with locked=true and empty settings. Other routes are denied until authenticated.
## POST /api/logout
{} => {ok:true}. Clear this browser's provider keys and roles. Hosted mode locks the session again. In-flight external requests are not cancelled or undone. Their stale responses are rejected, and no follow-on speech requests start after logout. Local processing is cancelled and server-staged materials are removed.

## POST /api/providers
{name,baseUrl,apiKey} => {provider: publicProvider}
Base URL includes API prefix, e.g. https://api.openai.com/v1 or https://gateway.example/api/v1. Remove trailing slashes, don't append a second /v1. HTTP permitted only localhost/127.0.0.1/[::1] for locally hosted providers. API key optional for local providers, required for remote. Keys are write-only. Add multiple providers (or edit an existing connection with PUT).
## PUT /api/providers/:id
{name,baseUrl,apiKey?} => {provider: publicProvider}. Keeps provider ID and model-role references. Blank API key retains the existing key only when the normalized URL is unchanged; changing to a remote URL requires re-entering a key. A changed URL/key clears listed models and sample checks. Rejects during an active AI job. No upstream request is made by editing.
## DELETE /api/providers/:id
=> {ok:true}; clears roles referencing that provider.
## POST /api/providers/:id/discover
{} => {models:[{id}]} from /models. Empty list and unsupported endpoint should explain manual model entry, not block saving provider.
## POST /api/providers/:id/probe
{model,kind:'text'|'vision'|'speech',api:'auto'|'chat'|'responses',voice?:string,reasoningEffort?:string,consent:true} => {check:{status:'verified'|'failed',detail,checkedAt,api,voice?}}
Optional explicit tiny billable requests. UI must label paid tests and request confirmation. Text/vision use primary API selection. Vision tests image understanding, not mere payload acceptance. Checks include reasoningEffort when explicitly configured and are scoped to the selected primary API mode/thinking level or speech voice; changing these settings makes the relevant badge untested until another check succeeds. Speech probes one short line; transcription is verified after a real upload, not a synthetic fake test, and is scoped to multipart versus Gemini-native mode.
## PUT /api/roles
{primary:Role|null,transcription:Role|null,speech:Role|null} => {roles}
Return selected model roles/count in UI; roles may reuse providers/models. Primary required to generate but can save null. Manual model IDs allowed. No fictitious model recommendations; show user-selected roles and untested status.

## POST /api/roles/recommend
{primary?:Role,scope?:'primary'|'all',consent:true} => {summary,suggestions:[{role:'primary'|'transcription'|'speech',selection:Role|null,reason,caveat}],warnings,advisor:Role}.
Uses the submitted primary draft or saved primary, including its thinking level. Explicit consent is required. Default scope includes only the primary provider; all scope shares other providers' catalogs with the primary advisor. Only catalog IDs, provider display names, scoped sample-check metadata and configured Kokoro availability are sent. No keys, base URLs, lesson material or internal provider IDs. Catalog includes listed and already-selected manual IDs; maximum 600 candidates. Unknown output candidates, invalid schema or settings changes during the call fail safely. Uses the normal AI job/session limits. Does not save roles or mark capability checks verified. UI renders text safely, lets users select which suggestions fill the draft, and requires a separate Save. Null selections mean abstain/preserve current choice.

## POST /api/speech/kokoro/probe
{voice?:string,consent:true} => {check}. Uses the included worker in the standard deployment, or an advanced operator-configured service. The service URL never comes from browser input. The app-only `npm run start:lite` developer mode without an external service returns a clear unavailable error. Native managed speech uses authenticated loopback HTTP with WAV output; its internal URL/token are never returned. `languages:['en']` and `voices` describe the native runtime's supported IDs; null means coverage is not advertised by an external/container service. Generates a short synthetic line and records the voice-specific result. Explicit local-test confirmation; no automatic cloud fallback. A returned supported audio format is not proof of naturalness or language quality.

## POST /api/lessons
{text:string,images:[{name,dataUrl}],language:string,level:string,subject:string,goal:string,includeAudio:boolean,consent:true,sourceWarnings?:string[],expectedSetupRevision?:number} => {id,title,html,warnings:[string],lesson:LessonSpec}
text up to 40k chars; up to 5 PNG/JPEG/WebP images, 4MB each and 8MB combined decoded; total HTTP body 13MB. These are final-request limits, not original-file cutoffs. The unified frontend automatically processes all document/media parts and reduces larger sources through consented digests first. Clipboard paste, drag/drop and file picker supported. sourceWarnings is bounded to 30 strings of at most 500 characters and persists into the export. Images require primary model vision capability; if untested show warning but let user request with data-processing notice. Inputs sent only to chosen provider on generate. Lesson model returns validated JSON and trusted renderer makes HTML; never execute arbitrary model HTML/JS. The complete-audio composer sends `includeAudio:false` here and uses the separate plan endpoints below. For backward compatibility only, `includeAudio:true` generates up to 8 sentences from lesson.audio using the selected provider speech role or configured Kokoro engine. Failures keep valid text lesson with warnings, never claim audio exists. User explicitly initiates paid generation. No pronunciation scoring yet. All subjects primary through university via free-form subject + AI auto-detect; depth/correctness requires human review.

LessonSpec = {title,subject,level,language,summary,objectives:[string],sections:[{type:'explanation'|'steps'|'example'|'vocabulary'|'quiz'|'summary',title,body:string,items:[string],question:string,answer:string,translation:string,source:string}],audio:[{text,translation}],warnings:[string]}. Fields required (empty strings/arrays okay); max 16 sections, 8 legacy `audio` script entries. Complete-mode targets are independently derived from every retained learning field and original source, not this legacy sample array. Flexible section order/type chosen by AI/request. Plain text math in MVP, no arbitrary scripts or diagrams. Source labels from provided input, never fabricated page references. HTML output is self-contained with escaped content, embedded generated audio, 1x/.75x/.5x speed, revealable hints/answers and source labels. It contains no credentials or external calls.

## Complete English audio plans

All endpoints retain authorization, same-origin and session-token checks. Plans and clip IDs are owner-scoped; no client filesystem paths or client-generated HTML are accepted. See [FULL-AUDIO.md](FULL-AUDIO.md) for coverage/language limits, privacy, quotas and session-only recovery.

- `POST /api/audio/preflight {}`: local managed-encoder and capacity checks, no AI/probe; may prepare pinned media assets. Returns `{ready,limits}`.
- `POST /api/audio/extract {image:{dataUrl},consent:true,expectedSetupRevision}`: one primary-model image recognition request. Both literal consent and the **current integer revision are mandatory**. Returns `{text,coverage:'complete'|'uncertain'|'no_english',warnings}`. All readable original English is requested, never a digest; even `complete` is not independent OCR verification. Maximum decoded image 4 MiB, recognized text 40,000 characters. No automatic retry after malformed/truncated/failed output.
- `POST /api/audio/plans {id:UUID,lesson:LessonSpec,images?:[],sourceText?:string,warnings?:[],expectedSources:[sourceKey],expectedSetupRevision}`: local creation with validated lesson/images and immutable speech identity. Same ID/content is idempotent; conflicting content is rejected. No provider request. Returns a manifest.
- `POST /api/audio/plans/:id/sources {source:{key,text,source,extraction,coverage,warnings}}`: add one declared source. Text is at most 40,000 UTF-16 characters; source label at most 300. `extraction` is `text|transcription|vision|unavailable`; `coverage` is `complete|uncertain|no_english|unavailable`. Identical key/content replay is local/idempotent; conflicts return409. The frontend automatically batches longer text without dropping tails.
- `POST /api/audio/plans/:id/seal {}`: require every declared source; freeze the deterministic inventory. No speech is dispatched.
- `GET /api/audio/plans/:id`: `{id,setupRevision,speech,summary,clips,sourceKeys,warnings}`. Summary includes `status:collecting|ready|partial|complete`, `totalClips`, `completedClips`, `totalUnits`, `sourceCount`, `expectedSources`, `bytes`, and separate `sourceUncertainties`. Clip views contain ID, status, attempt count and optional safe failure text, not source text or credentials.
- `POST /api/audio/plans/:id/reconfirm {consent:true,expectedSetupRevision}`: local adoption of the current revision **only if speech engine/provider base/model/voice still match**. A new voice/destination cannot silently reuse a plan. No provider request.
- `GET /api/audio/plans/:id/clips/:clipId`: `{clip,summary}`, strictly read-only status polling.
- `POST /api/audio/plans/:id/clips/:clipId {consent:true,expectedSetupRevision,attemptId:UUID,retry?:true}`: one small speech operation. Exact current revision and plan binding are mandatory. Capture the attempt before dispatch; a repeated attempt ID never causes another provider request. Completed clips are reused; failed/unknown/damaged clips need a new attempt ID and explicit retry consent. A retained raw speech result is encoded locally on recovery without repeating speech. Statuses: `pending|processing|complete|failed|encoding_failed|damaged`. A replay can return HTTP200 with a failed/processing status; callers must inspect it, not assume success. No speech endpoint fallback.
- `GET /api/audio/plans/:id/export`: trusted `{id,title,lesson,html,warnings,audioSummary}` with available MP3 assets embedded once. Verifies cached file hashes; damage downgrades coverage. Incomplete inventories/clips are explicitly labeled, never silently treated as complete. Busy export/clip operations return409; export itself never generates audio.
- `DELETE /api/audio/plans/:id`: cancel queued local work and remove owned temporary data. Already submitted provider work cannot be undone. Cleanup failures retain ownership/reservation for retry; no late results may resurrect a deleted plan.

All new inference endpoints use literal consent and mandatory revision checks. The UI shows an exact-count second speech confirmation, stops on any failed/unknown paid attempt, and resumes by plan ID without rerunning `/lessons`, source recognition or transcription. Unchanged-setup continuation can poll an in-flight clip without issuing a rebind write; changed setups wait for the existing operation before reconfirming. Encoding-recovery clips are resolved before other damaged clips because only one bounded raw result is retained per plan.

## Local material staging (no provider calls)
All routes retain session ownership/CSRF checks. `POST /api/materials` accepts `{id:clientUUID,name,size}`; repeating the same ID/name/size is idempotent. `GET /api/materials/:id` returns `{id,name,size,received,status,kind,partCount,duration?,hasAudio?,hasVideo?,pages?,warnings,error,chunkSize:4194304}`.

`PUT /api/materials/:id/content?offset=N` takes raw `application/octet-stream` bytes (at most 4 MiB). Upload sequentially; an identical chunk replay is safe, different content/offset conflicts return 409. `POST /api/materials/:id/finish` with `{}` performs bounded local extraction/probing and returns the manifest. `POST /api/materials/:id/parts` with `{index}` returns `{index,label,source,text,images,audio?,warnings,start?,end?}`. `DELETE /api/materials/:id` aborts local work and removes staging. No filesystem paths are accepted from clients. See IMPORTS.md for resource ceilings and format fidelity.

An earlier direct-document endpoint `POST /api/materials/import` also accepts bounded document bytes with `X-LearnLens-Filename`; the unified UI uses resumable staging instead.

## POST /api/materials/summarize
`{consent:true,text,images,source,goal,expectedSetupRevision?:number}` => `{text,warnings,preparationMode:'verbatim'|'model'}`. Image-free text already within the 2,200-character notes budget is retained locally without a provider request (`verbatim`), after existing input validation/boundary trimming. Longer text or any images use the primary model (`model`). This does not bypass transcription or final teaching. Consent, setup-revision, session and CSRF guards still apply to both modes. The UI labels local preparation separately from provider inference.

Model notes remain strictly bounded: a JSON object with nonempty `notes` (at most 2,200 UTF-16 characters) and `warnings` (0–5 nonempty strings, each at most 300 characters). Invalid notes are never truncated, accepted as a checkpoint, repaired through another paid call or silently retried. The prompt states these limits explicitly; this is not a guarantee that a model or gateway honors them. Output budgets/thinking settings are not automatically increased or downgraded.

A local validation failure returns HTTP 502 with `diagnostics.category:'preparation_validation'`, a fixed `validationReason` such as `digest_invalid_json`, `digest_notes_limit` or `digest_warning_limit`, and relevant character/count metadata. Sanitized upstream HTTP status, endpoint, response byte count, completion status and reported token counts are preserved when available. Thus app HTTP 502 can be distinguished from provider HTTP 200 with invalid notes. Bodies, notes, warning text, instructions, source labels and credentials are omitted from diagnostics. Explicit incomplete/refusal/tool-request text responses fail before notes validation; legacy omitted completion metadata remains supported, not independently verified.

The client performs bounded hierarchical reduction when necessary. Successful local and model preparation results are pinned in the current page's generation checkpoint; explicit continuation reuses them and retries only unfinished steps after renewed consent. Saved instructions/options apply; changed attachments block continuation. Reload, logout, expiry or app restart loses the checkpoint. No persistent browser storage is used.

`/materials/summarize`, `/transcribe` and `/lessons` require `consent:true` and reject a supplied stale `expectedSetupRevision` before invoking a provider. Legacy direct API callers must now include `consent:true`; the unified UI already supplies it only after confirmation. All new UI calls capture the revision when consent is given; the optional field preserves existing API clients. Paid calls are never automatically retried after a malformed, timed-out or unknown result. The narrowly scoped 404/405/501 Responses→Chat fallback remains the exception for primary API auto mode, never transcription.

## POST /api/transcribe
{dataUrl:'data:audio/wav;base64,...',name?:'recording.wav',consent:true,expectedSetupRevision?:number} => {text}
Default: selected provider `/audio/transcriptions` multipart. Accept webm,wav,mp3,mp4,ogg; <=8 MiB. Explicit transcription `api:'gemini'`: inline prepared WAV only, one non-streaming native `models.generateContent` call on the same provider. `/v1` becomes `/v1beta`, custom prefixes remain; other supported base shapes, authentication, model-ID constraints, response validation and limits are in [GEMINI-AUDIO.md](GEMINI-AUDIO.md). No model-name inference or native/multipart fallback, even on 404/405/501. Blocks, truncation, missing/non-text/empty output and the no-speech prompt sentinel fail without accepting a transcript. Frontend record via MediaRecorder if supported plus audio upload fallback. Ask before sending microphone data, stop tracks, show pending state. Automatic media preparation supplies independently playable WAV parts; successful transcripts are cached in-page and enter source-labeled preparation. No claims that transcription measures pronunciation.
